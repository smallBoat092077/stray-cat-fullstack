# 流浪猫喂养小程序 - 前端

## 项目简介

流浪猫喂养微信小程序前端，基于原生小程序框架开发。

## 项目结构

```
stray-cat-miniapp/
├── app.js              # 应用入口
├── app.json            # 应用配置
├── app.wxss            # 全局样式
├── project.config.json # 项目配置
├── sitemap.json        # 站点地图
├── images/             # 图片资源
── utils/
│   └── api.js          # API 封装
└── pages/
    ├── index/          # 首页（地图）
    ├── cat/            # 猫咪模块
    │   ├── list        # 猫咪列表
    │   └── detail      # 猫咪详情
    ├── feeding/        # 投喂模块
    │   ├── list        # 投喂任务列表
    │   └── detail      # 投喂任务详情
    ├── adoption/       # 领养模块
    │   └── apply       # 领养申请
    └── profile/        # 个人中心
```

## 功能模块

### 首页（地图）
- 显示附近流浪猫位置
- 点击标记查看猫咪详情
- 底部展示附近猫咪卡片
- 上报流浪猫入口

### 猫咪模块
- 猫咪列表（支持状态筛选）
- 猫咪详情（图片、信息、健康状态）
- 送猫粮入口与最近支持者
- 申请领养入口

### 投喂模块
- 投喂任务列表（待接单/已接单/已完成）
- 志愿者接单
- GPS打卡（距离校验）
- 上传打卡照片

### 领养模块
- 领养申请表单
- 住房、养猫经验等信息填写
- 提交审核

### 猫粮（打赏）模块
- 猫粮为站内虚拟道具，不可兑换现金、不可转让提现
- 免费获得途径：注册赠送 100、每日签到 5、上报猫咪 10、投喂打卡 50、领养回访 20
- 付费获得途径：购买「猫粮礼包」，走微信虚拟支付（道具直购），详见下方虚拟支付配置
- 送猫粮：选择份数（1~200）+ 留言，扣款与记录在同一事务内完成
- 猫咪详情展示累计猫粮与最近支持者（昵称脱敏）
- 我的猫粮：送出记录与收支明细分页查看

### 个人中心
- 用户信息展示
- 信用积分、投喂次数、服务时长
- 猫粮余额、每日签到、收支明细
- 我的领养、投喂记录
- 志愿者申请
- 隐私政策
- 退出登录 / 注销账号

## 快速开始

### 1. 安装微信开发者工具

下载地址: https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html

### 2. 导入项目

1. 打开微信开发者工具
2. 选择「导入项目」
3. 项目目录选择 `stray-cat-miniapp`
4. AppID 填写你的小程序 AppID（或选择测试号）

### 3. 配置后端地址

编辑 `app.js` 中的 `baseUrl`：
```javascript
baseUrl: 'http://localhost:8080/api'  // 开发环境
// baseUrl: 'https://your-domain.com/api'  // 生产环境
```

### 4. 运行

点击「编译」即可预览

## 注意事项

1. **AppID**: 需要在 `project.config.json` 中配置真实的 AppID
2. **域名配置**: 生产环境需要在小程序后台配置合法域名，且域名必须完成 ICP 备案
3. **位置权限**: 需要在小程序后台申请位置接口权限，并在「用户隐私保护指引」中声明收集的信息
4. **图片资源**: tabBar 图标与默认图片放在 `images/` 目录
5. **打赏不走现金**: 向猫咪「送猫粮」只扣站内猫粮，不产生资金流动；猫粮本身可以付费购买，走的是微信虚拟支付而非微信支付
6. **虚拟支付与微信支付是两套能力**: 个人主体不能开通微信支付，但可以申请「虚拟支付（道具直购）」。以微信后台的实际开通结果为准

## 虚拟支付（猫粮礼包）配置

1. 小程序后台 → 虚拟支付 → 基本配置，拿到 `OfferID` 与 `现网AppKey`；同时设置消息推送的 `Token`
2. 虚拟支付 → 道具管理，按 `application.yml` 里的 `product-id` 逐个创建道具（`catfood_60` / `catfood_320` / `catfood_680`），价格必须与 `price-fen` 一致，创建后需要发布并等同步生效
3. 密钥只放服务端，用环境变量注入，不要写进仓库或小程序包：
   ```bash
   export XPAY_OFFER_ID=你的OfferID
   export XPAY_APP_KEY=你的现网AppKey
   export XPAY_PUSH_TOKEN=消息推送Token
   ```
4. 消息推送 → 接收地址配置为 `https://你的域名/api/xpay/notify`，数据格式 XML 或 JSON 均可（服务端两者都解析），模式选明文
5. 回调通了之后可把 `xpay.reconcile-enabled` 设为 `true`，作为丢包时的查单兜底

要点：`signData` 由服务端序列化并签名，前端必须原样透传；到账只认服务端的发货通知与查单结果，不认前端的支付成功回调；`coin_transaction` 的 `uk_biz` 唯一键保证重复通知不会重复加猫粮。

完整的逐项配置与验收步骤（含资格、备案域名、IP 白名单、真机支付与退款验收）见仓库根目录的 `小程序后台配置核对清单.md`。

## 内容安全（UGC 检测）

昵称、打赏留言、猫咪资料与上报、领养申请与回访这些文本，服务端会调微信 `wxa/msg_sec_check`（version=2）检测后再入库：

- 命中 `risky` 直接返回 3012「内容包含违规信息」，写库与扣猫粮都发生在检测之后，被拒的提交不留脏数据
- `review` 与接口异常默认只记 WARN 放行；提审前把 `wechat.msg-sec-check.strict` 设为 `true`，两者都会拦
- 检测需要 openid，因此**只有微信登录的用户会被覆盖**；账号密码注册的账号跳过检测
- 实测「色情/赌博/办证」类样本返回 risky，但「出售枪支」类样本返回 pass——这个接口只能挡大部分垃圾内容，不能当作保证
